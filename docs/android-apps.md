## 18. סטודיו התרגום (v354–v355, שלבים 1–2 מתוך התוכנית שאושרה)
- **⛔ כל ההורדות של מנהל ההורדות — תמיד בטלפון, אף פעם לא בשרת (22/10/2026, החלטת המשתמש, אחרי שיוטיוב חסם את השרת)**: הבדיקה וההורדה = yt-dlp בתוך Studio לאנדרואיד (youtubedl-android 0.18.1: פייתון 3.12 + QuickJS + ffmpeg, GPL-3.0, arm64, minSdk 29 ל־Studio). האתר → `intent://probe|dl?…#Intent;scheme=snbstudio;package=app.thesnowball.studio` → `DlActivity` (חלון קטן) → בדיקה: חזרה ב־‎`#probe=<n>.<base64url>` (`studioProbeRes`, `normDevProbe`) · הורדה: `DlService` (שירות בחזית עם התראה) → `Movies/Studio` (MediaStore) → `MainActivity` עם share target → Chrome ‏POST ‏`/share-file` → `sw.js` (`shareFile`, IndexedDB ‏`snb-inbox`) → ‎`#got=<מפתח>` → `studioGot` → עבודה רגילה מהטלפון (הקול קודם; הטופס ב־sessionStorage ‏`pwa_studio_dlp`, כי ה־POST טוען את הדף מחדש). שגיאה → ‎`#dle=`. **`DlProbe.kt` = `fetchurl.summarize`/`selector`/`ERR_RULES`** (בדיקת JVM ‏`DlProbeTest` מול פלט של הפייתון ב־`testStudio/resources/dlprobe`; ‏`studio-devdl` משווה את הקודים) — שינוי באחד = בשני, ולהפיק מחדש את הקבצים. yt-dlp מתעדכן בטלפון (nightly, פעם ביום — `DlEngine.prepare`). **"ישר לענן של Studio" — רק בבחירה** (בקשת המשתמש באותו יום): בדף הקישור "לאן להוריד" — לטלפון (ברירת מחדל) / לענן (`startLinkCloud` → `spec.src='url'`, העובד מוריד), רק כש־`ui.url` ובמקור שלא חוסם את השרת (`cloudBlocked` — היום יוטיוב). בדפדפן בלי האפליקציה: הבדיקה בשרת (`linkCheckSrv`) וההורדה רק לענן. כל שם שעובר בין הצדדים (`video`/`text` ב־share target, ‎`snbdl:<n>`, ‎`#probe/#got/#dle`) — `tests/studio-devdl.test.js`.
- **העלאת הסרטון ב־Background Fetch (23/10/2026, בקשת המשתמש: "שממשיכה גם כשהאפליקציה סגורה")**: רק עבודה ב־R2, סרטון מ־64MiB (`BG_MIN`), לא "רק Wi‑Fi" (`bgEligible` ב־`studiobg.js`). **Chrome לא שולח ב־Background Fetch בקשה שצריכה CORS preflight** — לכן כל חלק = POST לנתיב `/up` **באותו מקור** (`functions/up.js`, Pages Function), שמעביר אותו ב־PUT לקישור החתום. `/up` מקבל **רק** קישור חתום לחלק של קובץ בסטודיו ב־R2 (`upTarget`: המארח, `st/<uid>/<מזהה>`, בדיוק הפרמטרים של חלק) — לא להרחיב לשער פתוח; Workers בחינם = עד 100MB לבקשה → חלק של 64MiB (`BG_PS`). השרתון: `op:'r2bg'` = קישורים לכל החלקים החסרים לשלושה ימים + מפתח סיום חד־פעמי (`fk`, ברשומה רק `bk` = hash); **`op:'r2bgDone'` בלי התחברות** — ה־service worker (`sw.js`, `backgroundfetchsuccess`) סוגר את ההעלאה ורושם את הסרטון (`r2Register`, משותף עם `op:'file'`), רק לשרתונים ב־`BG_API_RE`. הסרטון ברקע מתחיל רק אחרי הקול (`audioSettled` — אי אפשר להשהות אותו כמו `vGate`). **אחרי Background Fetch תמיד `r2Upload` הרגיל** — הוא סוגר כשהכל הגיע, או ממשיך מהחלקים החסרים; כך כל כישלון (דפדפן שלא תומך → `settings.bgNo` לחודש, `bad-status`, קישור שפג) חוזר להעלאה של היום. מחיקה/ביטול → `bgAbort`. **נבדק**: יחידה (`tests/studio-bgup.test.js`) + Chromium אמיתי (3 חלקים דרך `/up` ו־`backgroundfetchsuccess`); **באנדרואיד עוד לא** — האישור = הפריסה הראשונה בניסוי (פרויקט אחד דיווח שאנדרואיד דחה העלאה כזו; אז `unsupported` והעלאה רגילה). **26/10/2026 — באנדרואיד: בדרך כלל עובד ומסתיים (התראת הסיום), אבל Chrome לא מדווח `uploaded` לדף; ופעם אחת קיבל ולא התחיל** ("עלו 1KB" — `fmtSize(0)`). לכן ההתקדמות = מה שכבר ב־R2 (`o.poll` → `r2parts` כל 20 שנ׳ כשהדף מוצג, `partsBytes`), ושעון תקיעה סופר אותה (`bgStallLimit`, 2 דק׳ בלי בית) → ביטול והעלאה רגילה, פעמיים בטלפון = `bgNo`; כל החלקים ב־R2 = מחכים לסגירה של ה־service worker (שתי סגירות = r2_gone). **לא לסמוך על `bg.uploaded`/אירוע progress באנדרואיד.** **המתנה לאירוע של הדפדפן — תמיד עם גבול זמן ונפילה לדרך הרגילה.** **28/10/2026 — איטי מההעלאה הרגילה**: Chrome שולח חלק אחד בכל פעם בעדיפות נמוכה (בטלפון: 280–440KB/שנ׳ מול 2MB/שנ׳). כשהדף מוצג דקה והקצב מתחת ל־1MiB/שנ׳ → `bg_slow`: מבטלים וממשיכים בהעלאה הרגילה, `settings.bgSl` = 3 ימים בלי ברקע, `utl.bg` = 5 (`BG_SLOW_MS`, `BG_FAST_BPS`). **29/10/2026 (2.82.8) — לפי מצב הדף**: הדף מוצג = ההעלאה הרגילה תמיד (גם בהתחלה; Background Fetch ישן של העבודה מבוטל לפני); ברקע `BG_HAND_MS` (8 שנ׳) והקול כבר עלה → החלקים החסרים עוברים ל־Background Fetch (אותה העלאה ב־R2 ואותו `ps` — `r2bg` ממשיך את הקיימת); `visibilitychange` → visible = ביטול מיידי וחזרה לרגילה (`flip` ב־`upVideo`, החלפה לא נחשבת עצירה). כישלון של הרקע = עד סוף ההעלאה רק הרגילה (`bgOff`). `bgSl` כבר לא חוסם (`bgCan`).
- **הורדה מקישור (22/10/2026, בקשת המשתמש: "כמו IDM") — המסלול בשרת ("ישר לענן של Studio")**: `spec.src = 'url'` — רק במצב השרת, ‏R2 בלבד, מנהל / "כל המודלים" + הדגל `st_url`. הבדיקה: טלפון `urlProbe` → `studioProbe` → הסוכן (`probe_loop`, op `pq` עם טוקן השרת) מריץ `fetchurl.py probe` → `normProbe` (צורה קבועה — טקסט מאתר חיצוני). העבודה: `job.url_fetch` בתחילת `prepare` — הקול קודם ונרשם (`srcFile`), הסרטון ברקע, העותק המקומי במקום של `fetch_input`; שגיאה → `url_<קוד>` (ב־ERR_INFO/TRANSIENT/DET ובטקסט בטלפון). **כל כתובת שהעובד פותח — דרך `check_url`** (גם אחרי DNS; חומת האש של המארח חוסמת ממילא). **בלי לקבע `player_client`** — ברירת המחדל של yt-dlp מתחלפת כל כמה חודשים והיא הנכונה.
