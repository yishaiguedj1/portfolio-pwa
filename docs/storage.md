# אחסון, שירותים ומכסות

## 15. אחסון, שירותים ומכסות (מחקר 01/10/2026 — הפרטים והמקורות ב־`מחקר-אחסון-וקורא-ספרים.md`)

- **המפה**: האפליקציה — GitHub Pages (מ־v395 דרך Actions — `deploy.yml`, רק אחרי בדיקות ירוקות ואישור; סביבת הניסוי — Cloudflare Pages) (**כל הריפו מתפרסם**, כולל CLAUDE.md/היומן/tests/android — נבדק 200; `cache-control: max-age=600` קבוע); בדיקות/APK/יקום — Actions (חינם לריפו ציבורי); APK — Releases (עד 2GB לקובץ, בלי מגבלת תעבורה); השרתון — Vercel Hobby; התחברות + התיק — Firebase Spark (מסמך אחד `users/{uid}`); כל הכבד — `localStorage` בטלפון (אין IndexedDB).
- **מכסות חינם**: Pages — אתר 1GB, 100GB/חודש (רכה), 10 בניות/שעה (רכה, לא חל על פריסה דרך Actions), לא מסחרי. Vercel Hobby — מיליון קריאות, 4 שעות CPU פעיל, 360 GB־שעות, 100GB תעבורה, 100 פריסות ביום, עד 60 שניות, **רק לא־מסחרי**; חריגה מתמשכת → השהיית פריסה (אין חיוב). Firebase Spark — 1GiB, 50K קריאות/20K כתיבות ביום, מסמך עד 1MiB; **Cloud Storage לא זמין בחינם** (קבצים גדולים → Drive).
- **השימוש שלנו**: האתר <1%; טעינה מלאה = 14 קבצים, ~0.7MB דחוס. השרתון: ~900 קריאות בשעה כשהאפליקציה פתוחה (עד ~1,800 עם כרטיס פתוח, ~60 כשהשוק לא זז) → בהערכה 5–20% מהמיליון; תשובת מחירים ל־15 סמלים = 2.8KB דחוס (נמדד). Firestore — זניח.
- **סיכונים (לא עלות)**: (1) ~~`saveDBto`/`lsSet` בולעים חריגת מכסה~~ — **טופל 10/10/2026**: `lsPutCritical` לתיק ול־IBKR מפנה מטמונים (`LS_CACHE_PREFIXES`) ומציג `storageFull`; **מטמון חדש ב־localStorage = להוסיף ל־`LS_CACHE_PREFIXES`** (הבדיקה משווה לקבועים), נתון אישי — לעולם לא שם. (2) **origin משותף** — כל מה שמתפרסם תחת `yishaiguedj1.github.io/*` חולק `localStorage` עם האפליקציה, כולל ה־token של IBKR (`pwa_ibkr_v1`) → **אפליקציה חדשה עם תוכן חיצוני (ספרים, HTML) — רק על origin נפרד** (ארגון GitHub חינמי `<org>.github.io` או Cloudflare Pages `*.pages.dev`). (3) Pages מתפרס גם כשהבדיקות אדומות.
- **אסור להעביר את `portfolio-pwa` לארגון GitHub** — Vercel Hobby לא מתחבר לריפו של ארגון, והשרתון יפסיק להתפרס. (ארגון — רק לאפליקציה חדשה בלי Vercel.)
- **⛔ מכסת הקריאות של Firestore — 50 אלף ביום, והיא נגמרה פעם אחת (26/10/2026)**: כל לולאה ששואלת את השרתון כל כמה שניות = קריאה של Firestore בכל פנייה, גם כשאין כלום לעשות. שרת התרגום הפנוי לבדו צרך כ־45,800 ביום, והשירות כולו (כניסה, שמירה לענן, Studio) נפל עד חצות בשעון קליפורניה. **לולאה חדשה בעובד/בטלפון או פעולה חדשה של שרת** — אימות מול העותק בזיכרון (`SRV_LIGHT` ב־api/studio.js), בלי שאילתה בכל פנייה, ותרחיש ב־`tests/studio-fsreads.test.js` (התקרה: 20 אלף ביום לשרת פנוי). סימן התקלה: `fs_http_429` / `who:store` ב־`GET /api/session`.
- **קריאה מ־Firestore בפעולה שחוזרת — רק מה שהשתנה (26/10/2026, בנייה 543)**: שאילתה בלי סינון על אוסף שגדל (`studioJobs`, `studioLearn`) = קריאה לכל מסמך. בבדיקה המתוזמנת — `recentJobs` (טווח על `updated`, אינדקס אוטומטי), במרכז הניהול — `learnLoad` בזיכרון + `jobsSince`, ספירות R2 ו־`provUsage` במטמון. **שאילתה חדשה במסלול שרץ כל כמה דקות / בכל כניסה — עם טווח, מטמון או `aoGet`.** Firestore שלא ענה — 503, לא "לא מחובר"/401.
- **ווידג׳ט הניטור של מרכז הניהול (26/10/2026)**: מתרענן כל דקה כשהמסך דולק (`MonRefresh`, התראת RTC לא־מעירה + WorkManager כגיבוי), ולכן בשרתון כל מה שהוא קורא — מהזיכרון (`monCfg` 60 שנ׳, `aoGet`). מידע חדש בווידג׳ט = לבדוק שהוא לא מוסיף קריאה ל־Firestore בכל פנייה; Firestore שלא ענה בנתיב הטוקן = 503, לא 401 ("טוקן לא תקין" היה השקר של 25/10).
- **כל השירותים ושליחת המיילים (26/10/2026, `תוכנית-עמידות-שירותים.md` שלבים 1–2)**: `lib/services.js` — שירות חדש שנשענים עליו = שורה ב־`SERVICES` (עם קוד גיבוי, `none` = סיכון) + `SVC_NAME`/`SVC_BK` ומחרוזות `admSvc*` במרכז הניהול; מדד שנמדד — דרך `sysUsage/main` (לא קריאה לספק בכל פנייה). מיילים — רק דרך `lib/mailer.js` (שרשרת חינמית, 90% מכל מכסה, מפתחות בכספת `studioVault/_mail`), והקישור מ־Firebase בלי שליחה (`lib/fbadmin.js`); כל כשל → `mail_off` והטלפון נופל ל־Firebase — **אף פעם לא שירות בתשלום** (בקשת המשתמש). קוד במייל: רק HMAC במסמך, 10 דק׳, 5 ניסיונות, שימוש אחד. **רשומות הדומיין** — כל יום ב־`bk/<יום>/dns.txt.gz` (`lib/dnsexport.js`, טוקן `CF_DNS_TOKEN`), **לא בריפו** (ציבורי). Backblaze B2 — נדחה (בקשת המשתמש 26/10). `tests/mail-services.test.js`.
- **כתיבות ל־Firestore מהשרת הפנוי (27/10/2026)**: מסמך השרת נכתב ב־poll רק כש־`seenDue` (שינוי בדופק / עלייה / דגלים / ניקוי `job` / `SEEN_MS`) — שדה חדש בדופק שמישהו קורא בזמן אמת (מרכז הניהול, server-upgrade) = להוסיף ל־`hbKey`, אחרת יתעדכן רק כל 3 דק׳. `studio-fsreads` סופר גם כתיבות.
- **מנוחה לאנימציות (27/10/2026)**: אנימציה מתמשכת חדשה בהדר — גם ב־`html.calm` (‏`brandCalmWire` ב־core עוצר אחרי 25 שנ׳ בלי נגיעה). כתיבה ל־localStorage מלולאה חיה — לא בכל טיק (`quotesSaveSoon`). ‏`fetchVerified(p, true)` בהתקנה לוקח קובץ זהה מהמטמון הקודם.
